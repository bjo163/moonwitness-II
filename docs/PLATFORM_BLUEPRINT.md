# MOONWITNESS — PLATFORM BLUEPRINT

## 01 — PLATFORM POSITION

> **MOONWITNESS = A STORY & WITNESS PLATFORM**

The website is an interface to the platform, not the platform itself.

MoonWitness is designed to help people:

**CAPTURE → CONNECT → WITNESS → UNDERSTAND → PRESERVE → PROMOTE → MOVE FORWARD**

## 02 — PLATFORM LAYERS

### STORY
People, characters, events, memories, fragments.

### WITNESS
Observations, witness logs, signals, messages.

### RELATIONSHIP
Connections between people, events, messages, memories, and eras.

### NARRATIVE
Seduction, fault lines, villains, conflict, Sanity's Last Breath.

### PAST PRESENCE
What from the past is still present.

### TRANSITION
Audit → Evaluation → Balancing → Promoting.

### CHANGE
What changed and what comes next.

### EXPERIENCE
The web interface and interactive discovery layer.

## 04 — PLATFORM PRINCIPLE

The platform should be:

- Simple to create.
- Easy to connect.
- Easy to discover.
- Safe to leave unresolved.
- Easy to archive and reopen.
- Able to grow without forcing complexity.

## 05 — MVP

The first platform release only needs:

```
Entities
Events
Witness Logs
Messages

```

Narrative systems can be layered on incrementally:

## 07 — PLATFORM BOUNDARY

MoonWitness is **not required** to become a social network, enterprise CMS, or heavy workflow system.

Start with a lightweight content graph.

Add infrastructure only when real usage requires it.

## 08 — SUCCESS CRITERION

A first end-to-end loop must work:

```
EVENT
 → WITNESS
 → MESSAGE
 → PAST PRESENCE
 → AUDIT
 → EVALUATION
 → BALANCING
 → PROMOTING
 → CHANGE
 → NEXT ERA
```

If this loop is easy to create, edit, connect, and explore, the platform foundation is working.
